Scheduling Module

SyncUp — AI Operations Manager for Student Organizations

MEMBER A   Module 1 of 3  ·  api/app/features/scheduling/  ·  Monolith: FastAPI · React · Supabase Postgres · Microsoft Foundry

Architecture note. SyncUp is a single FastAPI process. "Scheduling", "resources", and "finance" are Python packages inside one application, not separate services. Every arrow in the diagrams below that crosses a module boundary is an in-process function call sharing one AsyncSession — no HTTP, no queue, no network hop.

1. Module Scope

The scheduling module turns a plain-English request in Discord into a ranked set of conflict-free meeting slots, then commits the chosen one as a confirmed event. It is the anchor module: resource planning and financial planning are both invoked from the event it creates.

4. Slot Scoring Algorithm

Deterministic and pure — the LLM parses and explains, it never scores. This is what makes the module demo-reliable and defensible to judges.

flowchart TD
  A["Parsed constraints"] --> B["Generate candidate slots
30-min granularity across window"]
  B --> C{"Inside org quiet hours?"}
  C -- yes --> X["Discard"]
  C -- no --> D["Join busy_blocks per member"]
  D --> E{"Hard conflict?
exam or class"}
  E -- "any required member" --> X
  E -- no --> F["Weighted attendance
sum of priority_weight of free members"]
  F --> G["Apply soft penalties"]
  G --> G1["late night after 21:00"]
  G --> G2["back-to-back with another org event"]
  G --> G3["exam week proximity"]
  G --> G4["fairness debt: member always excluded"]
  G1 --> H["score = attendance_pct * 100 - penalties"]
  G2 --> H
  G3 --> H
  G4 --> H
  H --> I["Deduplicate overlaps
best per 3-hour bucket"]
  I --> J["Rank desc, take top 5"]
  J --> K["Return to service.py for persistence"]

6. The Confirm Transaction — Monolith Payoff

This is the section that changed most from a service-oriented design, and it is the strongest technical argument for the monolith.

Confirming a slot must write to all three modules' tables: create the event, hold the resources, draft the budget. In one process this is a single database transaction. If the budget draft fails, the resource holds and the event roll back automatically — the org never ends up with a projector reserved for an event that does not exist.

# app/features/scheduling/service.py
from app.features.resources import service as resources_service
from app.features.finance   import service as finance_service

async def confirm_proposal(
    db: AsyncSession, proposal_id: UUID, actor_id: UUID
) -> EventPlan:
    """One transaction across all three modules.
    Either the whole plan commits, or none of it does."""

    async with db.begin():                       # BEGIN
        proposal = await _load_proposal(db, proposal_id)
        event    = await _create_event(db, proposal, actor_id)
        await _add_attendees(db, event, proposal)

        # Direct in-process calls. Same session, same transaction.
        # Not HTTP. Not a queue. Not a background task.
        reservations = await resources_service.plan_for_event(db, event)
        budget       = await finance_service.draft_for_event(db, event, reservations)

    # COMMIT happens here. Any exception above rolls back everything.
    return EventPlan(event=event, reservations=reservations, budget=budget)

Why not an event bus?

ApproachCostVerdict
Direct import + callCoupling between packagesUse this. Atomic, debuggable, zero infrastructure
In-process dispatcher (dict of hooks)Indirection; harder to trace in a stack traceAcceptable if you want looser coupling — still one transaction
Redis / Celery / RabbitMQExtra Render service, extra failure mode, eventual consistencyDo not. Zero demo value, real risk
Circular import warning. Scheduling imports resources and finance. If either of those imports scheduling back, Python will fail at startup. Rule: scheduling may import the other two; they must never import scheduling. If they need event data, they receive it as a function argument. If you hit a cycle anyway, move the shared types into app/core/types.py.
