1. What This Covers

This is the practical, click-by-click companion to the architecture described in the Team Handbook. It walks through creating the actual Discord application, wiring its credentials into the SyncUp bot skeleton already in api/app/bot/, running it locally, and using or extending the two commands currently registered: /inventory and /packing-list.

3. Create the Discord Application

  1. Go to the Discord Developer Portal and sign in.
  2. Click New Application, top right. Name it SyncUp (or SyncUp-dev if you want a separate dev bot from the demo bot).
  3. On the General Information page, optionally set an app icon and description — this is what shows up in the server member list, worth doing before a demo.
  4. In the left sidebar, click Bot.
  5. Click Reset Token (first time it's called this even though nothing existed before) → confirm → copy the token immediately. Discord shows it exactly once; if you lose it, reset again.
Treat the token like a password. Anyone with it can control your bot. Never commit it — it goes in .env, which is already in .gitignore. If a token is ever pushed to a public GitHub repo, Discord auto-revokes it and you'll need to reset again.

4. Configure the Bot User

Still on the Bot page:

  • Under Privileged Gateway Intents, enable Message Content Intent. This lets the bot read message text, needed if you later want @SyncUp mention-based requests in addition to slash commands. Slash commands alone don't strictly need it, but the client is already configured to request it (app/bot/client.py sets intents.message_content = True), so the gateway connection will fail without it.
  • Leave Public Bot on unless you specifically want only you to be able to invite it.

5. Generate the Invite Link

  1. Left sidebar → OAuth2 → URL Generator.
  2. Under Scopes, check bot and applications.commands. The second is required — without it, slash commands never appear in the server even if the bot is online.
  3. Under Bot Permissions, check: Send Messages, Embed Links, Use Slash Commands, Read Message History.
  4. Copy the generated URL at the bottom, paste it into a browser, pick your test server, and authorize.

You should now see the bot listed in your server's member sidebar, showing offline (it isn't running yet).

6. Environment Variables

You need your server's ID for guild-scoped command sync (see §12 for why this matters). In Discord: User Settings → Advanced → Developer Mode (toggle on), then right-click your server icon → Copy Server ID.

cd syncup/api
cp .env.example .env

Fill in .env:

# --- Discord ---
DISCORD_BOT_TOKEN=<paste the token from step 3>
DISCORD_GUILD_ID=<paste your server ID>
DISCORD_ANNOUNCE_CHANNEL_ID=            # optional for now — used later for #events announcements

# --- App ---
ENVIRONMENT=development

7. Install & Run

cd syncup/api
uv venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
uv pip install -e ".[dev]"

uvicorn app.main:app --reload --port 8000

The bot runs as a background task inside the FastAPI process (see app/main.py's lifespan), so starting the API also starts the bot — there's nothing separate to launch.

8. Verify It's Online

  • Terminal should log SyncUp online as SyncUp#XXXX.
  • http://localhost:8000/health should return {"status": "ok"}.
  • In your Discord server, the bot should now show online in the member list.
  • Type / in any channel the bot can see — /inventory and /packing-list should appear in the autocomplete list within a few seconds (guild sync is near-instant; see §12 if they don't show up).

10. How Commands Are Wired

Three pieces, so it's clear where to hook in:

FileRole
app/bot/client.pyCreates the single shared discord.Client and app_commands.CommandTree. Calls each feature's register(tree) function. Handles guild-scoped sync in on_ready.
app/bot/commands/resources.pyDefines a register(tree) function that adds /inventory and /packing-list to the shared tree using @tree.command(...) decorators.
app/bot/embeds.pyShared embed builders (info_embed, success_embed, warning_embed, error_embed, conflict_field, packing_list_embed) so every feature's replies look like one product instead of three different bots.

The pattern for another feature module (e.g. Member A's scheduling commands) is identical: a commands/scheduling.py with its own register(tree), imported and called once from client.py.

11. Adding a New Command

Example: adding a /reserve command to commands/resources.py.

# inside register(tree) in app/bot/commands/resources.py

@tree.command(name="reserve", description="Hold a resource for an event window")
@app_commands.describe(
    item="Resource name, e.g. 'Projector'",
    hours="How many hours to hold it for",
)
async def reserve(interaction: discord.Interaction, item: str, hours: int) -> None:
    await interaction.response.defer(thinking=True)

    # TODO: call resources.service.hold(...) once it exists
    embed = embeds.success_embed(
        f"Reserved: {item}",
        f"Held for {hours}h. (stub — not yet backed by real availability check)",
    )
    await interaction.followup.send(embed=embed)
  • Always defer(thinking=True) before any work that isn't instant — Discord kills an un-acknowledged interaction after 3 seconds, and an LLM or DB round trip is slower than that. Reply with interaction.followup.send(...) afterward, not interaction.response.send_message(...).
  • Restart uvicorn after adding a command — the tree is built at import time.
  • New commands appear in Discord within seconds because sync is guild-scoped, not global.

12. Troubleshooting

SymptomLikely causeFix
Slash commands never appearMissing applications.commands scope when generating the invite URL, or synced globally instead of to the guildRe-invite with the correct scope; confirm client.py is syncing via tree.sync(guild=...), not a bare tree.sync()
Bot shows offlineInvalid or unset DISCORD_BOT_TOKEN, or the process crashed on startupCheck the terminal output for the exception; re-copy the token from the Bot page (reset it if unsure)
PrivilegedIntentsRequired error on startupMessage Content Intent not enabled in the Developer Portal, but requested in codeBot page → Privileged Gateway Intents → enable Message Content Intent
"The application did not respond" in DiscordA command handler took longer than 3 seconds before respondingAdd await interaction.response.defer(thinking=True) as the first line, then followup.send(...)
Command shows in Discord but running it does nothing / errors silentlyException raised inside the handler after defer()Check the uvicorn terminal log — discord.py logs the traceback there, not in Discord
Changed a command but Discord still shows the old versionDiscord caches command definitions client-side brieflyRestart your Discord client, or wait ~1 minute; guild sync itself is near-instant server-side
401 Unauthorized on startupToken was reset in the portal after .env was last filled inCopy the current token again — old tokens are invalidated on reset
